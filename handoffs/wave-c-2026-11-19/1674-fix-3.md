## The gap that was repaired

A queued handoff watcher returned silently when its seat's pane was `gone` or `finished`, or the
terminal's `created_ms` moved, before the restart (`runQueuedRestart`), and the `finally` removed
the queue entry. No `handoff-failures.json` row was written, the project's main bot was not told,
and a later `am restart --queued` showed nothing. The detached watcher's stderr dies with its
`--rm` pane, so the direct pass's own `report()` could not cover it, while the direct pass already
recorded the same event as `dropped` (`restartDuePass`'s `waitForHandoff` not-live path). The
direct pass's pre-ask and post-cancel pane deaths were output-only (the reviewer's MEDIUM).

## What changed

- `herdr/mods/am-sidebar/bin/automagik-herdr.mjs`
  - `runQueuedRestart`'s not-live check now calls `noteHandoffFailure(entry, "dropped", …)` with
    the default main-bot notification before returning, with an honest `why` for `gone`,
    `finished`, and a reused `created_ms` (both values named). Nothing gives up silently.
  - The fire-time `cmdRestart` `PRINTED` return is covered too: if the queue entry still exists
    (a person's cancel removes it), the watcher records the pane gone/finished/reused/no-longer-live
    drop instead of returning silently.
  - `restartDuePass`: the pre-ask and post-cancel `paneNow` not-live paths now write the same
    `dropped` row, say it on stderr and in the pass summary, and keep exit 0 for a seat that was
    already gone (the reviewer's "the exit code can stay 0").
- `am/bin/automagik-herdr.mjs` — resynced byte copy (`am-copies --write`), 48 files match.
- `herdr/test/cli.test.mjs` — four new `#1556` tests (below) and a `captainDueScene`/
  `queueCaptainDue`/`waitForDroppedHandoff` harness; every existing row kept.
- `herdr/test/fake-hc.mjs` — `onSendWrite` (the handoff lands during the ask's round trip),
  `afterKill` (the seat ends when the plain queue entry is canceled), and the `onRead` counter is
  now saved on every look so `nth` can name a later read; `onRead`'s `nth: 1` behavior is unchanged.

The row shape is the existing one: `{at, kind, botId, botName, project, terminal, handoff, why,
report, notified}`; kind `dropped`; one row per bot, newest first, 20-row bound, 0600, atomic
replace, corrupt JSON parsing to `[]` — no second file or schema.
